# Design pillars

Five tests. A feature that fails one is usually the wrong feature.

## 1. Satisfying

Every interaction produces **movement, sound, VFX and a physical response**. Nothing in this game
happens silently or instantly.

> **The test:** if you removed the number that changed, would the moment still feel good?

## 2. Visible progression

Progress is legible without opening a menu: a bigger magnet model, faster movement, larger objects,
deeper environments, a physically larger robot, new parts bolted on, visible damage, arena status.

> **The test:** could a player who never reads the HUD tell they got stronger?

## 3. Risk versus reward

The farther you go: better parts, heavier cargo, stronger security, harder escape. Depth is not just a
bigger number, it is a worse situation.

> **The test:** does going one zone deeper cost something other than time?

## 4. A personal robot

The robot is not purchased at a level. It is assembled from objects the player physically retrieved. Two
players' robots should be immediately distinguishable at a glance.

> **The test:** can you tell whose robot it is from across the Arena?

## 5. Constant life

The world is almost never static. Conveyors, machinery, lighting, particles, scrap, robots, arena
fights, events, refreshes.

> **The test:** if the player stands still for ten seconds, does anything move?

---

## The core design rule

Section 86, applied to every proposed feature:

> **Does it make finding, pulling, escaping with, building from, or fighting with physical objects more
> interesting?**

If not, it probably does not belong in MAGNET SWEEP.
